## Design Specificity Verdict

DESIGN.md's system (One Signal Rule, Weight-Over-Size Rule, Structural Breakpoint Rule) is real and followed on the best pages (CareGaps.jsx, AuditCompliance.jsx, Labs.jsx). ## Overall Impression

The system is real and mostly good where it's followed — CCM.jsx's draft/commit separation and CareGaps.jsx's AI-outreach flow are genuinely well-executed, product-specific design. The problem is enforcement, not intent: a documented, disciplined design system (DESIGN.md) coexists with 482 undocumented off-palette colors, measured-failing contrast on every page tested, zero error/disabled input states, and zero accessibility affordances anywhere in a live app handling real patient data. The single biggest opportunity is closing the gap between the system as written and the system as shipped — most of these are enforcement/retrofit fixes (tokens, states, a shared confirm dialog), not a redesign.

## What's Working

1. **CCM.jsx's draft/committed care-plan state separation** (`planTasks/planGoals/careTeam` vs. `editTasks/editGoals/editCareTeam`) is a precise UI implementation of PRODUCT.md's "AI assists, clinicians decide" principle — an unreviewed AI draft structurally cannot reach the billable plan.
2. **CareGaps.jsx's AI-outreach chat-bubble UI** is the most disciplined, fully token-driven page in the app (`PRIORITY_STYLES`/`STATUS_STYLES` built entirely from `var(--danger/warning/success/primary)`) and the detector found no color findings there.
3. **Labs.jsx's `RangeBar` + `Sparkline` + `TEST_REFERENCE` auto-fill** turns data entry into a guided, scannable clinical judgment tool — strong recognition-over-recall execution.

## Priority Issues

**[P0] No error or disabled states anywhere in the form/input system**
- **Why it matters:** `index.css` contains exactly one disabled rule (`.btn:disabled`) and zero error/invalid input styling app-wide — DESIGN.md itself flags this as an open gap. In a live clinical data-entry app, a form that can't visually signal "invalid" or "locked" risks silent errors on real patient records.
- **Fix:** Define `.form-input:invalid`/`.form-input.error` (danger-token border + inline message) and `.form-input:disabled` (muted background, no pointer) in `index.css`; retrofit Patients.jsx add/edit, Labs.jsx result entry, and CCM.jsx plan editing first.
- **Suggested command:** `/impeccable harden`

**[P0] Destructive clinical-record actions use native `window.confirm()`**
- **Why it matters:** 9 files (Patients, Consent, Appointments, AdverseEvents, Channels, NLPNotes, Labs, FloatingChat, PopulationHealth) delete records via an unbranded, unstyleable native dialog with no room to explain consequences and no keyboard/screen-reader-friendly custom flow — dangerous on real patient-record deletion.
- **Fix:** Build one shared `<ConfirmDialog>` component (token-styled; require typing the record name for the highest-risk deletions) and swap all 9 call sites to it.
- **Suggested command:** `/impeccable harden`

**[P1] Design-system drift: undocumented second accent color, systemic off-palette usage**
- **Why it matters:** DESIGN.md's One Signal Rule states Clinical Teal is the only accent, with no documented exception — yet App.jsx, BetaGate.jsx, and AiHelp.jsx independently default to purple `#8b5cf6`/`#7c3aed`, and the detector counted 482 off-palette color instances across 38 files (30× for `#7c3aed` alone), live-confirmed on `/billing` via browser injection. This is systemic drift that will keep getting copy-pasted into new surfaces if left undocumented.
- **Fix:** Either formally document a scoped "beta accent" exception in DESIGN.md (gate/help chrome only, never data or CTAs) or remove the purple defaults and route accent through `--primary` everywhere; then sweep the top offenders (NLPNotes.jsx, FloatingChat.jsx, Patients.jsx, Discharge.jsx, CaseReview.jsx) back onto tokens.
- **Suggested command:** `/impeccable clarify`

**[P1] Accessibility is functionally absent, and measured contrast fails on every page tested**
- **Why it matters:** Zero `aria-label`, zero `role`, zero `:focus-visible` across all 39 page/component files (confirmed by grep), combined with browser-measured contrast ratios of 2.6:1–4.0:1 against badges and body text on every one of 5 pages tested (dashboard, patients, ccm, billing, care-gaps) — all below the 4.5:1 WCAG AA minimum. PRODUCT.md itself already flags accessibility as an open gap; this is now a measured, not theoretical, finding in a live app used by care teams daily.
- **Fix:** Add `:focus-visible` rings (teal token) to `.btn`/`.form-input`/nav links in `index.css`; add `aria-label`s to icon-only controls (close buttons, chevrons, calendar prev/next) starting with Layout.jsx and Admin.jsx; fix the semantic badge tint/text pairs in DESIGN.md itself so success/warning/danger badges clear 4.5:1.
- **Suggested command:** `/impeccable harden`

**[P2] Dashboard's mental model mismatches the product's stated CCM/RPM identity**
- **Why it matters:** Dashboard.jsx organizes the landing screen around acute-care triage categories (Cardiology/Respiratory/Neurology/GI/Infectious/Musculoskeletal/General via `presenting_complaint`) and surfaces urgent case counts as the primary metric, while PRODUCT.md defines the product's core identity as CCM/RPM chronic-care coordination — which lives only behind the `PBeta`-gated `/ccm` and `/rpm` routes, disconnected from the home screen. The first thing a returning user sees frames the app as ER triage, not chronic-care management.
- **Fix:** Promote CCM/RPM summary stats (billing-eligible minutes, active care plans, device-online counts) onto the main Dashboard, or reframe its stat cards around chronic-care operations rather than acute triage.
- **Suggested command:** `/impeccable layout`

## Persona Red Flags

**Alex (Power User):**
- Blocked by the 15-item Layout.jsx sidebar every session — no search, pinning, or collapsing to reduce recall burden.
- Every destructive action interrupts flow with a native `window.confirm()` rather than an inline, keyboard-dismissable, branded confirmation.
- Silent `catch {}` blocks in Admin.jsx mean a failed save (`toggleActive`, `savePassword`) gives no feedback — a bulk user-management session could silently fail with no error toast.

**Sam (Accessibility-Dependent):**
- Zero `aria-label`s means every icon-only button (AiHelp.jsx close, Layout.jsx nav chevrons, Appointments.jsx calendar prev/next) is announced as unlabeled to a screen reader.
- Zero `:focus-visible` rules means no visible keyboard-focus indicator anywhere — measured browser evidence confirms this isn't just a source-code gap: badge and body text also fail WCAG AA contrast (2.6–4.0:1 vs. the 4.5:1 minimum) on every page tested, so even sighted-but-low-vision use is compromised, not just screen-reader use.
- `window.confirm()` dialogs are (accidentally) natively accessible — the one part of the deletion flow that works for Sam by default.

**Jordan (First-Timer):**
- Login.jsx's marketing claims ("1000+ Patients," "Trusted by clinical teams worldwide," "SOC 2 aligned") contradict PRODUCT.md's explicit "no fabricated testimonials/press" rule and set a jarring first impression; the same page also triggers `overused-font` (Inter 100% of text) and a decorative `codex-grid-background` finding from the detector.
- `PatientPortal.jsx` — the component PRODUCT.md describes as the patient-facing "viewing check-ins, readings, care plan status" experience — has **no registered route in App.jsx** and is entirely unreachable; the first-timer patient experience PRODUCT.md promises does not currently exist in the shipped app.
- The BetaGate passcode flow (`BETA_PASSCODE = '1906'`, hardcoded, shared) gives no explanation of what CCM/RPM even are before demanding a passcode.

## Minor Observations

- Login.jsx's error state uses its own rose palette instead of `--danger`/`--danger-light` — the app's one clear error state is itself inconsistent with error states elsewhere.
- Detector-only findings not otherwise covered above: `side-tab` colored-left-border accents (11 instances, flagged as an AI-generated-UI "slop" tell) across AdverseEvents, ChronicDisease, ClinicalDecisions, Interoperability, Labs, NewCase, SharedCase, logs/CasesPanel, FhirPreview; `flat-type-hierarchy` on `/patients` (11 sizes spanning only 1.7:1); `layout-transition` on progress-bar width animations (CCM.jsx, Patients.jsx, NLPNotes.jsx) — likely negligible in practice given the small, infrequently-updated elements involved.
